补环境

“补环境” 的完整说法是 “补充浏览器环境” 或 “伪造浏览器环境”。

它的核心思想是：在非浏览器环境（如Python的js2py、execjs，或Node.js）中执行JavaScript代码时，通过手动模拟实现浏览器提供的各种原生对象和方法，从而欺骗目标JS代码，让其误以为自己正在真实的浏览器中运行，从而顺利执行并得出正确结果。

  • 简单的网址可以通过扣代码完成 复杂的网址通过伪装环境会简单很多

非常有必要掌握浏览器接口对象常用的

  • window
    • navigator 提供浏览器、操作系统和设备的静态/半静态信息
    • navigation 浏览器历史导航、路由管理
    • location 当前页面的 URL信息
    • history 用于操作浏览器的会话历史（前进、后退）
  • document
    • element 节点信息
  • screen 屏幕信息
  • localStorage和sessionStorage：本地存储对象
  • 网络请求 xhr jsonp等

难点

  • 如何找到缺少的环境
  • 如何很好的实现环境代码;

vm2

node中vm2模块

切断 Node.js 的干扰痕迹：浏览器环境有 window、navigator 等对象，而 Node.js 则提供了 process、global 等属性。反爬虫的 JS 代码很可能会检查这些差异，如果发现环境是 Node.js，就会拒绝运行。vm2 创建的沙箱会严格限制掉 Node.js 的特有属性

书写环境框架

JSDOM

https://github.com/jsdom/jsdom 主要适用于参考

jsdom 是一个在 Node.js 中模拟浏览器 Web 标准（DOM、HTML、部分浏览器 API）的库。 它让 Node.js 拥有一个“假的浏览器窗口”，能解析 HTML、构建 DOM 树，并暴露出 window、document、navigator 等对象

  1. 一键提供逼真的浏览器环境 不用你手动伪造 document.createElement、element.innerHTML、addEventListener 等数百个 API。jsdom 直接帮你造好了一个兼容性很高的虚拟 window，被执行的 JS 代码就像在真实浏览器里操作 DOM 一样。
  2. 解析 HTML 并执行内联 / 外部脚本 你可以把目标网页的 HTML 扔给 jsdom，它会构建 DOM 树，并自动执行 `` 标签里的 JS——包括那些用来生成加密参数、计算反爬指纹的脚本。
  3. 串联 Node.js 与前端逻辑 比如你在 Python 里调用 Node 脚本，用 jsdom 加载页面后，直接 window.getSignature() 拿结果，再通过 stdout 传给 Python。

在 Node.js 中创建虚拟浏览器环境，然后在里面执行 JS 代码并拿结果

安装使用

npm install jsdom

function vmProxy(obj, name = 'unknown') {
    return new Proxy(obj, {
        set(target, prop, newValue, receiver) {
            const valueType = typeof newValue;
            console.log(
                `方法:set 对象:${name} 属性:${String(prop)} 新值:${newValue} 属性类型:${valueType}`
            );
            return Reflect.set(target, prop, newValue, receiver);
        },
        get(target, prop, receiver) {
            const value = target[prop];
            const valueType = typeof value;
            console.log(
                `方法:get 对象:${name} 属性:${String(prop)} 属性类型:${valueType} 属性值:${value === undefined ? 'undefined' : value}`
            );
            return value;
        }
    });
}

伪装函数代码

避免被检测出是伪装的函数

// 主要用来保护伪造的函数 让其更难被识破
(() => {
    "use strict";
    const $toString = Function.toString;
    const myFunction_toString_symbol =  Symbol('('.concat('', ')_',(Math.random() + '').toString(36)));
    const myToString = function() {
        return typeof this == 'function' && this[myFunction_toString_symbol] || $toString.call(this);
    };
    function set_native(func, key, value) {
        Object.defineProperty(func, key, {
            "enumerable": false,
            "configurable": true,
            "writable": true,
            "value": value
        });
    }
    delete Function.prototype['toString'];
    set_native(Function.prototype, "toString", myToString);
    set_native(Function.prototype.toString, myFunction_toString_symbol, "function toString() { [native code] }");
    this.func_set_native = (func) => {
        set_native(func, myFunction_toString_symbol, `function ${myFunction_toString_symbol,func.name || ''}() { [native code] }`);
    };
}).call(this);

xuxin_proxy 代理功能

根据配置决定是否对传入的对象（如 window、document、location）包装成 Proxy

当 config.proxry = true 时，所有对该对象的属性读取（get）和赋值（set） 都会在控制台打印出来

xuxinvm.proxy = function (obj) {
  if (!xuxinvm.memory.config.proxry) { return obj }
  return new Proxy(obj, {
    set(target, prop, newValue, receiver) {
      console.log("set", target, prop, newValue)
      return Reflect.set(target, prop, newValue, receiver)
    },
    get(target, prop, receiver) {
      console.log("get", target, prop);
      return target[prop];
    }
  })
};
