scrapy的概念

是一个为了爬取网站数据，快速提取结构性数据而编写的应用框架

作用: 通过少量的代码，就能够快速的抓取 ,框架是代码的半成品，主要作用提高效率（爬虫效率和开发效率）

官网地址: http://scrapy-chs.readthedocs.io/zh_CN/1.0/intro/overview.html

  • Scrapy 带有内置的并发设置
  • Scrapy 带有请求地址去重

scrapy的流程

模块作用

  • 引擎(engine)：负责数据和信号在不同模块间的传递(中枢控制器，协调所有组件的数据流)

  • 调度器(scheduler)：管理待爬取的 Request 队列（URL 构成的请求对象）比如: 去重

  • 下载器(downloader)：接收引擎发过来的request请求，获取响应，并将响应交给引擎

  • 爬虫(spider)：处理引擎发过来的response，提取数据，提取url，并交给引擎

  • 管道(pipeline)：处理引擎传递过来的数据，比如存储

  • 下载中间件(downloader middleware)：可以自定义的下载扩展，比如设置代理ip

    • 预处理 Request（如自动重试、更换代理）
    • 后处理 Response（如修改响应内容、过滤异常页面)

  • 爬虫中间件(spider middleware)：可以自定义request请求和进行response过滤，与下载中间件作用重复

    • 干预 Spider 的输入（Response）和输出（Item/Request）

其流程可以描述如下：

用户运行爬虫脚本后，Scrapy初始化后，先加载 Spider 中定义的起始 URL

  1. 将Spiders的URL
    • 传输 → Spider Middlewares(爬虫中间件) 进行设置请求对象
    • 传输 → Scrapy Engine(引擎 ==> 控制中心)
  2. Scrapy Engine接收spider middleware 数据信息
    • 将数据信息发送 → scheduler(调度器)进行处理
  3. scheduler将接收到的数据信息(request)生成队列 (管理request请求的)
    • 将request请求信息发送 → Engine引擎,再发送 → Downloader middleware(下载中间件)
    • 从下载中间件发送 → downloader(下载器)
  4. downloader接收请求信息
    • downloader 获取请求信息后,会请求对于的网络地址的数据,并返回数据response
    • 将response数据返回 → Downloader middleware(下载中间件) → Engine引擎将response数据发送 → Spider Middlewares(爬虫中间件) → Spiders
  5. Spiders 解析 Response，提取数据或新链接
    • 新 Request → 返回给 Engine，进入下一轮调度
    • 结构化数据（Item） → 引擎→ 交给 Item Pipeline 处理。

注意: 去重是根据url进行去重的

Scrapy

windows/Mac安装命令

pip/pip3 install scrapy

项目流程命令

  1. 创建项目: scrapy startproject 项目名
  2. 创建一个爬虫: scrapy genspider 文件名称 爬虫的网页域名
    • 创建后会生成在spider文件夹中
    • 示例: scrapy genspider lianjia cs.lianjia.com
  3. 提取数据: 根据网站结构在spider中实现数据采集相关内容
  4. 保存数据: 使用pipeline进行数据后续处理和保存

目录结构如下

  • scrapy.cfg 项目配置文件， 不需要做改动
  • items.py 定义数据存储模型
  • middlewares.py 用于编写中间件（下载中间件+爬虫中间件） -- 无特殊需求，一般不需要编写
  • spiders文件夹定义的爬虫文件 lianjia.py （爬虫文件,文件名称自己定义） [后面再来完善该爬虫模块]
  • pipelines.py 管道 -- 主要用于编写数据处理步骤 （数据的清洗+保存）
  • settings.py 详细的配置信息（设置文件USER_AGENT 并启动管道)

请求头与响应头属性

request请求对象的常用属性

  1. request.url（必选）：请求页面的url地址，bytes或str类型。
  2. request.callback：页面解析函数，Callback类型，Request请求对象的页面下载完成后，由该参数指定的页面解析函数解析页面，如果未传递该参数，默认调用Spider的parse方法。
  3. request.method：HTTP请求的方法，默认为‘GET’。
  4. request.headers：HTTP请求的头部字典，dict 类型。
  5. request.meta：Request 的元数据字典，dict 类型，用于给框架中其他组件传递信息，比如中间件 Item Pipeline。其他组件可以使用Request 对象的 meta 属性访问该元数据字典 (request.meta), 也用于给响应处理函数传递信息。
  6. request.encoding：url 和 body 参数的编码默认为'utf-8'。如果传入的url或body参数是str 类型，就使用该参数进行编码。
  7. request.dont_filter：默认情况下（dont_filter=False）,对同一个url地址多次提交下载请求，后面的请求会被去重过滤器过滤（避免重复下载）。如果将该参数置为True，可以使请求避免被过滤，强制下载。例如：在多次爬取一个内容随时间而变化的页面时（每次使用相同的url），可以将该参数设置为True。

response响应对象的常用属性

  1. response.url：获取当前响应的url地址
  2. response.request.url：获取当前响应对应的请求的url地址
  3. response.headers：获取响应头
  4. response.urljoin(url) ：用于构造绝对url, 当传入的url参数是一个相对地址时, 根据response.url计算出相应的绝对url.
  5. response.body：获取响应体，也就是html代码，byte类型
  6. response.text： 获取响应体，str类型
  7. response.status：获取响应状态码
  8. response.json(): 获取json数据

自定义请求

yield scrapy.Request(url,callback) 设置请求并指定回调函数

  • callback=self.parse 指定回调函数执行
  • method='GET'
  • headers=None 请求头字典
  • body=None 请求体（POST数据）
  • meta=None 传递额外数据的字典
  • dont_filter=False 为True请求不会调度器过滤
    • 遇到重定向时会触发
      • 需要设置dont_filter=False 不设置会被scrapy调度器过滤掉请求

中间件设置

中间件可以设置多个, 会按照数值执行

爬虫中间件

  • from_crawler: 创建中间件实例时调用
  • process_spider_input: 每个响应进入spider之前调用
    • 既引擎将响应数据返回值spider中时触发
  • process_spider_output:
    • spider处理完响应后，生成的Request或Item即将返回给引擎时调用
  • process_spider_exception: 当spider或process_spider_input方法抛出异常时，这个方法被调用
  • process_start: 是异步方法，用于处理异步起始请求
  • spider_opened 当 Scrapy 引擎完成爬虫初始化后执行
    • 记录日志

下载中间件

  • from_crawler: 创建中间件实例的
  • process_request: 每个通过下载器中间件的请求都会调用
  • process_response: 对每个从下载器返回的响应都会调用
  • process_exception : 当下载处理器或process_request方法抛出异常时调用
  • spider_opened 当 Scrapy 引擎完成爬虫初始化后执行
    • 记录日志的
    • 启动浏览器实例（如配合 Selenium或DrissionPage）

自动抓取链接

基础

from scrapy.spiders import CrawlSpider, Rule

Scrapy 框架中用于构建 规则爬虫（CrawlSpider） 的关键导入语句

  • CrawlSpider 是Scrapy提供的一个通用爬虫，允许你定义一些规则进行自动提取链接并打开页面获取数据
  • 特点：
    • 自动根据预设规则（Rule）提取页面中的链接。
    • 适合爬取目录型网站（如新闻网站、博客、电商商品列表）
  • Rule 定义爬虫的链接提取和跟进规则, 主要包括：
    • 如何从页面提取链接（使用 LinkExtractor）。
    • 是否跟进这些链接（follow=True/False）。
      • True: 提取链接对应的A页面之后, 会继续使用相同的Rule,从A页面中提取链接,并跟进到下一页面中
      • False: 只提取一次;
        • 会提取链接,并提取链接对应的页面, 但不会从这个页面中继续提取链接并跟进
        • 执行 callback 指定的解析函数处理这个页面
    • 如何处理提取的链接（回调函数 callback）。

from scrapy.linkextractors import LinkExtractor

是 Scrapy 框架中用于 从网页中自动提取链接 的核心组件，通常与 CrawlSpider 和 Rule 配合使用

  • LinkExtractor: 定义如何从页面提取链接。

  • 用XPath限定提取链接的区域

    • restrict_xpaths='//div[@class="pagination"]'

  • 用CSS选择器限定提取区域

    • restrict_css='.pagination'
    • 用正则表达式匹配允许的链接
      • allow=r'/product/\d+'（匹配 /product/123/）

使用

分页获取

  • parse是默认执行函数,用于处理rule规则,不可修改
  • parse_start_url : 专门处理 start_urls 中的初始页面
  • 没有详情的时候,会使用

# 通过LinkExtractor进行自动翻页
import scrapy
from scrapy.spiders import CrawlSpider, Rule
from scrapy.linkextractors import LinkExtractor

class ExampleSpider(CrawlSpider):
    name = "example"
    allowed_domains = ["toscrape.com"]
    start_urls = ["https://books.toscrape.com/"]

    rules = [
        Rule(
            LinkExtractor(
                # 会自动提取这个a标签的href
                restrict_xpaths='//li[@class="next"]/a'
            ),
            callback='handles_message',
            # true 通过链接获取当前页面之后,在获取当前页面的下次
            # 连接进行打开,
            follow=True
        )
    ]
    
     # 首页的数据会进入此处
    def parse_start_url(self, response):
        """专门处理起始URL（首页）"""
        return self.parse_page(response)  # 调用通用页面解析

    # 通用解析 只会第二页的数据, 第一页不会获取
    def handles_message(self, res):
        # 自动进行翻页处理
        title = res.xpath('').extract()
        print(title, "数据")
        print("============")
